## 1. Auth model

Two independent auth domains. Nothing is shared between them.

**Learnable Meta** — bearer token in the standard `Authorization` header. There is no custom `X-Api-Key` header anywhere in the script. The only place headers are attached to a learnablemeta.com call is `requestJson` (line 5500):

```js
// lines 5500-5508
function requestJson(url, apiToken) {
  return new Promise((resolve, reject) => {
    _GM_xmlhttpRequest({
      method: "GET",
      url,
      headers: {
        Authorization: `Bearer ${apiToken}`,
        "Content-Type": "application/json"
      },
```

Timeout is 15 s (5509). Non-2xx rejects with `LearnableMetaApiError(status, message)` where the message prefers `body.message` (5521-5527). A `401` is treated as "token rejected": the stored key is cleared and the token prompt is re-shown (6167-6173, 6219-6225).

Token storage and provenance:
- stored in userscript storage under `learnableMeta_apiKey` (5711, via `_GM_getValue`/`_GM_setValue`, 5713-5722)
- generated by the user at `https://learnablemeta.com/profile/token` (5712)

**GeoGuessr** — no token at all, session cookies only. `geoguessrAPIFetch` (5561) calls plain `fetch` and never sets `credentials`, which defaults to `same-origin`; the script runs on `www.geoguessr.com`, so the session cookie rides along. Only `Content-Type: application/json` is set (5564). The two cross-origin GeoGuessr reads set `credentials: "include"` explicitly (4283, 6027).

Consequence for a reimplementation: a server can call every learnablemeta.com endpoint with the bearer token, but the GeoGuessr draft/publish calls must run in the browser (userscript) or carry a copied `_ncfa` session cookie.

## 2. Learnable Meta endpoints

### 2.1 `GET /api/userscript/map/{geoguessrId}` — map info (keyless)

- URL: `https://learnablemeta.com/api/userscript/map/${geoguessrId}` (4238)
- No auth. Fetched by `fetchMapInfo` (4186-4211) with a bare `_GM_xmlhttpRequest`, no headers.
- `200` and `404` are both treated as success and parsed as JSON (4192).

Verified live:

```
GET https://learnablemeta.com/api/userscript/map/66c0d3feff4dbe492e06174e
{"mapFound":true,"isPersonal":false,"userscriptVersion":"0.93"}
```

Fields consumed: `mapFound` (4232, 6042), `isPersonal`, `userscriptVersion` (4251, 6047).
Client caches 24 h when `mapFound`, 1 h when not (4212-4213, 4232).

### 2.2 `GET /api/userscript/location` — per-location meta (keyless)

- URL: `https://learnablemeta.com/api/userscript/location?${urlParams}` (4941)
- Query params, built at 4935-4940: `panoId`, `mapId`, `userscriptVersion`, `source`.
  - `mapId` is the GeoGuessr map id.
  - `panoId` is the **decoded** pano id — GeoGuessr serves it hex-encoded and `decodePanoId` (4295-4301) converts hex pairs to chars before the request (6045).
  - `source` is one of `"map"`, `"challenge"` (5225, 5297) or `"liveChallenge"` (5407).
- No auth header (4942-4945). Confirmed live: an unknown panoId returns `404`, not `401`.
- `404` means "meta for this location not found" (4958-4959).

Response fields consumed by the meta panel: `country` (5121), `metaName` (5122), `note` (5091, rendered as HTML), `footer` (5097, HTML), `images` (5111, array for the carousel).

**This is the endpoint that carries the meta text, and it is per-pano, not per-map.**

### 2.3 `GET /api/userscript/map/{geoguessrId}/locations` — synced locations (bearer)

- URL: `https://learnablemeta.com/api/userscript/map/${geoguessrId}/locations${query}` (5553)
- Optional query param `expectedFingerprint`, URL-encoded (5551):
  `?expectedFingerprint=<sha256hex>`
- Auth: `Authorization: Bearer <token>` via `requestJson`. Confirmed live: `401 Unauthorized` without a token.

```js
// lines 5550-5560
async function fetchSyncedMapLocations(geoguessrId, apiToken, expectedFingerprint) {
  const query = expectedFingerprint ? `?expectedFingerprint=${encodeURIComponent(expectedFingerprint)}` : "";
  const data = await requestJson(
    `https://learnablemeta.com/api/userscript/map/${geoguessrId}/locations${query}`,
    apiToken
  );
  if (!Array.isArray(data.customCoordinates)) {
    throw new LearnableMetaApiError(0, "Received invalid map location data");
  }
  return data.customCoordinates;
}
```

**Response shape:** a single object with a `customCoordinates` array (5556). Nothing else in the response is read.

**Per-location meta association: no.** The script never reads a meta name or meta id off these objects. The only per-location fields the code touches are the six used for fingerprinting (6052-6055):

```js
const tuples = coordinates.map(
  ({ panoId, lat, lng, heading, pitch, zoom }) => [panoId, lat, lng, heading, pitch, zoom]
);
```

The array is otherwise passed **verbatim** into the GeoGuessr draft body (5653, 6272), so if the server does attach extra per-location fields they would be forwarded to GeoGuessr untouched — but no such field is named anywhere in the userscript. Grep for `extra` / `tags` in the bundle returns nothing. Meta lookup happens later and separately, per pano id, through §2.2.

Two call sites, differing only in `expectedFingerprint`:
- single-map upload: called without it (5641)
- group update: called with the manifest's fingerprint (6270), i.e. an optimistic-concurrency assertion that the server's locations still match what the manifest advertised

`expectedFingerprint` is `row.fingerprint` from the map-group manifest (§2.5) — the fingerprint of the Learnable Meta side, not of the GeoGuessr draft.

Empty array is a hard error: "Cannot publish an empty map" (5647-5651, 6271).

## 3. GeoGuessr endpoints (session cookies only)

### 3.1 Draft URL builder

```js
// lines 5603-5605
function draftUrl(geoguessrId) {
  return `https://www.geoguessr.com/api/v4/user-maps/drafts/${geoguessrId}`;
}
```

### 3.2 `GET /api/v4/user-maps/drafts/{id}` — read draft

`getGeoguessrDraft` (5606-5609), no query params, no body.

Fields read off the response: `avatar`, `description`, `highlighted`, `name`, `version` (5611) and the coordinate list, which may arrive under either key (6068-6071):

```js
function getGeoguessrDraftCoordinates(draft) {
  if (Array.isArray(draft.coordinates)) return draft.coordinates;
  if (Array.isArray(draft.customCoordinates)) return draft.customCoordinates;
  return [];
}
```

### 3.3 `PUT /api/v4/user-maps/drafts/{id}` — write locations

```js
// lines 5610-5623
async function updateGeoguessrDraft(geoguessrId, draft, customCoordinates) {
  const { avatar, description, highlighted, name, version } = draft;
  await geoguessrAPIFetch(draftUrl(geoguessrId), {
    method: "PUT",
    body: JSON.stringify({
      avatar,
      description,
      highlighted,
      name,
      customCoordinates,
      version: version + 1
    })
  });
}
```

Exact JSON body:

```jsonc
{
  "avatar":       <echoed from GET>,
  "description":  <echoed from GET>,
  "highlighted":  <echoed from GET>,
  "name":         <echoed from GET>,
  "customCoordinates": [ /* verbatim array from LM /locations */ ],
  "version":      <GET version + 1>
}
```

Notes for a reimplementation:
- It is a full replace, not a patch — the whole coordinate array is sent every time.
- The five metadata fields must be round-tripped from the `GET`; the script never invents them.
- `version` must be incremented by exactly 1 (5620). This is GeoGuessr's optimistic-concurrency check, so always `GET` immediately before `PUT`.
- Locations are **not** re-encoded. Whatever Learnable Meta returned is what GeoGuessr receives. Per-location fields evidenced in the code: `panoId`, `lat`, `lng`, `heading`, `pitch`, `zoom` (6054). No wrapping object around each location — `customCoordinates` is a flat array of those objects.

### 3.4 `PUT /api/v4/user-maps/drafts/{id}/publish` — publish

**A separate publish step exists.** Draft updates do not go live on their own.

```js
// lines 5624-5629
async function publishGeoguessrDraft(geoguessrId) {
  await geoguessrAPIFetch(`${draftUrl(geoguessrId)}/publish`, {
    method: "PUT",
    body: JSON.stringify({})
  });
}
```

Method `PUT`, body is the literal empty object `{}`, no query params.

The two stages are tracked and retried independently, which confirms they are genuinely separate: statuses `update-error` vs `publish-error` (6274, 6282), the label `"Draft updated; publish failed"` (6320), and a retry path that re-publishes without re-uploading (6294-6301).

### 3.5 Supporting GeoGuessr reads (not part of sync)

- `GET https://game-server.geoguessr.com/api/live-challenge/{id}`, `credentials: "include"` (4281-4284). Reads `data.options.mapSlug`, `data.currentRoundNumber`, `data.rounds[i].question.panoramaQuestionPayload.panorama.panoId` (4286-4291).
- `GET https://www.geoguessr.com/api/v3/results/highscores/{resultsToken}?friends=false&limit=1`, `credentials: "include"` (6026-6027). Reads `data.items[0].game.map` and `.rounds[].panoId` (6033, 6045).

Both return hex-encoded pano ids that must go through `decodePanoId` (4295-4301) before hitting §2.2.

## 4. Fingerprinting (change detection)

The userscript decides "does this map need updating" locally, by comparing a hash of the GeoGuessr draft's coordinates against the `fingerprint` the manifest supplies.

```js
// lines 6052-6066
function canonicalizeMapCoordinates(coordinates) {
  const tuples = coordinates.map(
    ({ panoId, lat, lng, heading, pitch, zoom }) => [panoId, lat, lng, heading, pitch, zoom]
  );
  tuples.sort((left, right) => {
    const leftJson = JSON.stringify(left);
    const rightJson = JSON.stringify(right);
    return leftJson < rightJson ? -1 : leftJson > rightJson ? 1 : 0;
  });
  return JSON.stringify(tuples);
}
async function fingerprintMapCoordinates(coordinates) {
  const bytes = new TextEncoder().encode(canonicalizeMapCoordinates(coordinates));
  const digest = await crypto.subtle.digest("SHA-256", bytes);
  return Array.from(new Uint8Array(digest), (byte) => byte.toString(16).padStart(2, "0")).join("");
}
```

Algorithm: map each location to the 6-tuple in that exact order, sort by the JSON string of each tuple, `JSON.stringify` the array of arrays, SHA-256, lowercase hex. Any server-side implementation must reproduce this byte for byte, including JS number formatting.

## 5. Call sequences

### 5.1 Single map — `uploadLocations(geoguessrId, apiKey)` (5630-5667)

1. `GET` geoguessr draft (5633) — fails hard with "Could not fetch map details"
2. `GET` LM `/locations` **without** `expectedFingerprint` (5641)
3. abort if empty (5647)
4. `PUT` draft with locations + `version+1` (5653)
5. `PUT` draft `/publish` (5661)

No fingerprint check on this path — it always uploads.

### 5.2 Group sync — `scanGroup` / `updateMap` (6187-6284)

1. `GET` `/map-groups` if no group preselected (6165)
2. `GET` `/map-group/{id}/maps` (6198)
3. per map, 3 workers in parallel (6216): `GET` geoguessr draft, fingerprint it, mark `changed` if it differs from `row.fingerprint` (6233-6236)
4. user selects; then **sequentially** per map (6253-6255): re-`GET` draft, re-check fingerprint and skip if now equal (6265-6268), `GET` `/locations?expectedFingerprint=<row.fingerprint>` (6270), `PUT` draft (6272), `PUT` publish (6279)
